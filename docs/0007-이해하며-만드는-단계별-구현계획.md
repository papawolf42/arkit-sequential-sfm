# 0007 — 이해하며 만드는 단계별 구현계획

## 먼저 할 일

첫 단위는 실제 `transforms.json`의 프레임 수와 첫 프레임을 출력하는 것이다.

```bash
uv run python tools/inspect_capture.py data/demo-day-latest/capture/transforms.json
```

사용자는 출력의 `file_path`, `timestamp`, `transform_matrix`, `fl_x/fl_y/cx/cy/w/h`가 무엇인지 하나씩 확인한다. 이 명령은 데이터를 읽기만 한다. 행렬 해석·좌표 변환·품질 검증은 아직 하지 않는다.

## 1. 목표와 협업 방식

최종 목표는 RGB·ARKit 정보로 카메라와 희소 기하를 검증하고 실제 3DGS 학습 결과 `splat.ply`를 만드는 것이다. 동시에 사용자가 대부분의 구현을 설명할 수 있어야 한다.

매 단위는 다음 순서로 진행한다.

1. 개념 하나와 입력·출력을 설명한다.
2. 사용자가 결과를 예상한다.
3. 작은 테스트를 작성하고 구현 부재로 실패하는 것을 확인한다.
4. 최소 코드만 구현한다.
5. 테스트와 실제 데이터 실행을 확인한다.
6. 사용자가 코드를 이해하고 결과를 확인한 뒤 다음 개념으로 간다.

- 거대한 사전 학습이나 완성품 복사를 요구하지 않는다.
- 필요한 수학은 해당 개념에서만 다룬다. 논문 → 개념·수식 → 공식 구현 → 작은 검증을 연결한다.
- 커밋은 반드시 사용자에게 명시적 컨펌을 받은 뒤 한다. 구현 요청이나 테스트 통과는 커밋 승인이 아니다. push도 별도 승인 사항이다.
- 첫 요청에서 승인된 작은 구현은 아래 A1까지다. 이후 단계는 이 문서가 존재한다는 이유만으로 자동 실행하지 않는다.

## 2. 설계 문서를 읽는 기준

현재 docs/0001~0006과 색인을 읽었다. 0006을 주된 설계 참고로 쓰되, 코드·API·실제 데이터로 검증한다. 설계서의 예시 수치와 품질 효과는 검증된 사실이 아니다.

- SfM도 잘못된 매칭과 보정 오차를 포함할 수 있다.
- 모든 카메라를 등록하는 것과 공통 관측으로 연결하는 것은 다르다.
- 희소점을 워핑해도 조밀한 벽 전체의 관측은 생기지 않는다.
- 다른 표면의 깊이를 평균하면 가짜 중간 표면이 생길 수 있다.
- 0004의 개념적 DA3 호출과 깊이 설명을 그대로 복사하지 않는다. 0006과 실제 공식 API·모델 출력으로 확인한다.
- 0002의 요약 JSON만으로는 모든 후보 쌍의 거리·방향을 계산하기에 정보가 부족하다. 프레임별 자세를 전달하는 계약을 해당 단계에서 정한다.
- 0006의 홀드아웃 제안은 전체 240장 학습과 구별한다. 평가 범위 변경은 사전에 합의한다.

## 3. 개념 단위 로드맵

각 항목은 별도의 작은 변경 후보다. 아래 단계 전체를 한 커밋으로 묶지 않는다.

### A. 사진 한 장의 데이터를 읽기

- [ ] A1. JSON을 읽어 프레임 수와 첫 프레임 출력. 코드·실제 실행 검증과 별개로 사용자 이해 확인이 필요하다.
- [ ] A2. 첫 이미지 경로를 찾아 파일 존재 확인.
- [ ] A3. 전체 프레임의 파일 존재·중복·이미지 크기 검사.
- [ ] A4. timestamp의 순서·누락·간격 검사.

산출물: 데이터 구조를 확인하는 리포트. GPU·매칭·AI는 사용하지 않는다.

### B. 카메라 위치와 좌표계

- [ ] B1. 행렬에서 카메라 위치를 꺼내 의미 설명.
- [ ] B2. 인접 카메라 이동 거리 계산.
- [ ] B3. 시선 방향·상대 회전각 계산.
- [ ] B4. camera-to-world와 world-to-camera의 변환·역변환 검증.
- [ ] B5. 3D 점 하나를 이미지 픽셀로 투영.
- [ ] B6. 사진 리사이즈·방향과 내부 파라미터의 일치 확인.

산출물: 촬영 경로와 이미지에 표시한 투영점. 좌우 반전·회전·축 오류가 있으면 다음 단계로 가지 않는다. 원본 좌표계 태그와 실제 저장 행렬을 확인하기 전 축 반전을 적용하지 않는다.

### C. 비교할 사진 쌍 선택

- [ ] C1. 시간상 이웃한 사진 쌍 생성.
- [ ] C2. 대칭 쌍·자기 쌍·중복 제거.
- [ ] C3. 이동 거리와 시선 방향으로 추가 후보 선정.
- [ ] C4. 재방문 후보를 별도 기록. ARKit 근접만으로 실제 루프로 승인하지 않는다.
- [ ] C5. 선정 이유와 예산·연결성 리포트 저장.

산출물: 매칭 쌍 파일과 후보 그래프. 후보 연결과 검증된 매칭 연결을 구분한다.

### D. 대응점과 희소 3D 점

- [ ] D1. 한 이미지의 특징점 표시.
- [ ] D2. 두 이미지의 대응점 표시.
- [ ] D3. RANSAC 등으로 잘못된 대응 걸러내기.
- [ ] D4. 알려진 자세로 점 하나 삼각측량.
- [ ] D5. 점을 원래 사진에 재투영해 관측과 비교.
- [ ] D6. 전체 데이터로 확장하며 트랙·유효 연결·미지원 프레임 기록.

특징점 추출·매칭은 COLMAP을 활용한다. 투영과 삼각측량은 작은 직접 구현으로 의미를 익힌 뒤 라이브러리 결과와 비교한다. 초기 희소 출력은 COLMAP 카메라·이미지·3D 점이며 학습된 Gaussian PLY와 다르다.

### E. 카메라 보정

- [ ] E1. 재투영 잔차와 최적화 목적 이해.
- [ ] E2. 기준 좌표와 척도를 고정하는 이유 확인.
- [ ] E3. 작은 구간의 Bundle Adjustment와 전후 비교.
- [ ] E4. 검증된 연결을 바탕으로 전체 보정·재삼각측량.
- [ ] E5. ARKit 상대 자세 제약은 별도 실험으로 추가.

pose-only 프레임은 원래 자세를 보존하고, 실제 관측으로 보정된 카메라 수를 별도 보고한다. 커스텀 최적화기는 기본 흐름 이해 후 검토한다.

### F. RGB-only 3DGS 기준 결과

- [ ] F1. 선택한 실제 학습기의 데이터 계약·버전 확인.
- [ ] F2. 카메라·희소점 출력 연결.
- [ ] F3. 실제 학습·PLY 내보내기.
- [ ] F4. 뷰어에서 품질 확인하고 기준 결과 보존.

AI 깊이를 추가하기 전에 시간·메모리·입력 범위·시각 품질을 기록한다. 전체 학습은 Window42 우선이며 실제 자원 상황을 확인한다. 업로드 API 성공이나 테스트 PLY는 실제 학습 증거가 아니다.

### G. 깊이 정보와 융합

- [ ] G1. Z-depth·역깊이·광선 거리 구분.
- [ ] G2. DA3 실제 출력과 카메라 조건부 입력 확인.
- [ ] G3. 희소 기하와 AI 깊이의 척도 비교·정렬.
- [ ] G4. 픽셀 하나를 다른 카메라로 워핑.
- [ ] G5. z-buffer와 가림 검사.
- [ ] G6. 다시점 일관성과 독립 관측 지지 검사.
- [ ] G7. 출처·전파 횟수·신뢰도·UNKNOWN을 보존하는 융합.
- [ ] G8. 동일 카메라·초기점·학습 조건에서 깊이 손실 효과 비교.

불확실한 곳을 억지로 채우지 않는다. 카메라가 바뀌면 관련 워핑·융합 캐시를 무효화한다.

## 4. 범위와 완료 기준

- 한두 사진의 실험은 이해를 위한 도구이며 최종 전체 240장 재구성을 대체하지 않는다.
- 서버·UI는 당분간 변경하지 않는다. 오프라인 처리를 검증한 뒤 연결한다.
- 각 단계의 구현·자동 테스트·실제 데이터 실행·사용자 이해·시각 검증·커밋 승인을 따로 관리한다.
- 지금은 A1을 구현·검증하는 범위다. 이 문서는 SfM·깊이·학습의 구현 완료를 주장하지 않는다.

## 5. 첫 코드 읽기 안내

`tools/inspect_capture.py`를 위에서 아래로 읽는다.

1. `argparse`: 터미널에서 받은 JSON 경로를 해석한다.
2. `Path.read_text`: 파일을 UTF-8 문자열로 읽는다.
3. `json.loads`: 문자열을 Python 딕셔너리·리스트로 바꾼다.
4. `manifest['frames']`: 프레임 목록을 선택한다.
5. `len(frames)`: 프레임 수를 얻는다.
6. `frames[0]`: 첫 프레임을 선택한다. 빈 목록이면 `None`을 출력한다.
7. `json.dumps`: 결과를 읽기 쉬운 JSON 문자열로 출력한다.

이번 코드는 JSON 형식·필수 필드 오류가 있으면 Python 오류로 종료한다. 친절한 오류 메시지, 이미지 파일 검사, 포즈 검증은 다음 범위이며 아직 지원한다고 주장하지 않는다.

첫 사용자 확인 질문: 출력의 `frames`는 어떤 자료형이며, `frames[0]`은 무엇인가? `transform_matrix`를 아직 계산하지 않아도 된다.
