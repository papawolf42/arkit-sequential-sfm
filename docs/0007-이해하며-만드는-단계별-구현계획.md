# 0007 — 이해하며 만드는 단계별 구현계획

## 먼저 할 일

첫 단위는 실제 `transforms.json`의 프레임 수와 첫 프레임을 출력하는 것이다.

```bash
uv run python tools/inspect_capture.py data/demo-day-latest/capture/transforms.json
```

사용자는 출력의 `file_path`, `timestamp`, `transform_matrix`, `fl_x/fl_y/cx/cy/w/h`가 무엇인지 하나씩 확인한다. 이 명령은 데이터를 읽기만 한다. 행렬 해석·좌표 변환·품질 검증은 아직 하지 않는다.

## 1. 목표와 협업 방식

최종 목표는 RGB·ARKit 정보로 카메라와 희소 기하를 검증하고 실제 3DGS 학습 결과 `splat.ply`를 만드는 것이다. 동시에 사용자가 대부분의 구현을 설명할 수 있어야 한다.

매 단위는 다음 순서로 진행한다.

1. 다음 한 개념의 작은 범위를 정해 테스트를 먼저 작성하고 실패를 확인한다.
2. 최소 구현 후 테스트와 실제 데이터 실행을 확인한다.
3. 변경 코드와 원리를 설명하고 사용자 확인을 받는다.
4. 구현 전에 매번 이해 확인 질문으로 멈추지 않는다. 커밋은 승인 후 실행하고 push도 함께 수행한다.

- 거대한 사전 학습이나 완성품 복사를 요구하지 않는다.
- 필요한 수학은 해당 개념에서만 다룬다. 논문 → 개념·수식 → 공식 구현 → 작은 검증을 연결한다.
- 커밋은 반드시 사용자에게 명시적 컨펌을 받은 뒤 한다. 구현 요청이나 테스트 통과는 커밋 승인이 아니다. 사용자의 상시 요청에 따라 승인된 커밋은 push까지 함께 수행한다.
- 첫 요청에서 승인된 작은 구현은 아래 A1까지다. 이후 단계는 이 문서가 존재한다는 이유만으로 자동 실행하지 않는다.

## 2. 설계 문서를 읽는 기준

현재 docs/0001~0006과 색인을 읽었다. 0006을 주된 설계 참고로 쓰되, 코드·API·실제 데이터로 검증한다. 설계서의 예시 수치와 품질 효과는 검증된 사실이 아니다.

- SfM도 잘못된 매칭과 보정 오차를 포함할 수 있다.
- 모든 카메라를 등록하는 것과 공통 관측으로 연결하는 것은 다르다.
- 희소점을 워핑해도 조밀한 벽 전체의 관측은 생기지 않는다.
- 다른 표면의 깊이를 평균하면 가짜 중간 표면이 생길 수 있다.
- 0004의 개념적 DA3 호출과 깊이 설명을 그대로 복사하지 않는다. 0006과 실제 공식 API·모델 출력으로 확인한다.
- 0002의 요약 JSON만으로는 모든 후보 쌍의 거리·방향을 계산하기에 정보가 부족하다. 프레임별 자세를 전달하는 계약을 해당 단계에서 정한다.
- 0006의 홀드아웃 제안은 전체 240장 학습과 구별한다. 평가 범위 변경은 사전에 합의한다.

## 4. 범위와 완료 기준

- 한두 사진의 실험은 이해를 위한 도구이며 최종 전체 240장 재구성을 대체하지 않는다.

- 각 단계의 구현·자동 테스트·실제 데이터 실행·사용자 이해·시각 검증·커밋 승인을 따로 관리한다.
- 현재 후보 방식은 fafd809에 커밋·푸시한 로컬 1,884쌍이다. C3 거리·각도 함수와 C3a 겹침 함수는 비교·보류 코드이며 현재 선정에는 사용하지 않는다. C4·C5는 보류한다. D1 첫 사진 추출은 실제 실행 완료, 시각화·자동 테스트 보강·전체 추출은 미완료다. B6b는 D3~D5에서 실제 대응점으로 확인한다. E~G의 큰 목표는 유지하되 D6의 기하 지지 확인 전 자동 진행하지 않는다. 이 문서는 SfM·깊이·학습의 구현 완료를 주장하지 않는다.

## 5. 첫 코드 읽기 안내

`tools/inspect_capture.py`를 위에서 아래로 읽는다.

1. `argparse`: 터미널에서 받은 JSON 경로를 해석한다.
2. `Path.read_text`: 파일을 UTF-8 문자열로 읽는다.
3. `json.loads`: 문자열을 Python 딕셔너리·리스트로 바꾼다.
4. `manifest['frames']`: 프레임 목록을 선택한다.
5. `len(frames)`: 프레임 수를 얻는다.
6. `frames[0]`: 첫 프레임을 선택한다. 빈 목록이면 `None`을 출력한다.
7. `json.dumps`: 결과를 읽기 쉬운 JSON 문자열로 출력한다.

이번 코드는 JSON 형식·필수 필드 오류가 있으면 Python 오류로 종료한다. 파일 존재 검사와 첫 카메라 위치 출력은 추가되었다. 친절한 오류 메시지, 이미지 내용 검사, 실제 대응점 기반 포즈 검증은 아직 지원하지 않는다.

첫 사용자 확인 질문: 출력의 `frames`는 어떤 자료형이며, `frames[0]`은 무엇인가? `transform_matrix`를 아직 계산하지 않아도 된다.
