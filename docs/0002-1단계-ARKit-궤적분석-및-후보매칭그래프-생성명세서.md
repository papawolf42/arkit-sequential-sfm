# 0002: 1단계 — ARKit 궤적 분석 및 후보 매칭 그래프 생성 명세서

본 문서는 개발자가 즉시 TDD(Test-Driven Development)로 구현할 수 있도록, **1단계: ARKit 궤적 분석기(`tools/analyze_trajectory.py`)** 및 **후보 매칭 그래프 생성기(`tools/build_matching_graph.py`)**의 상세 규격과 테스트 요구사항을 정의한다.

---

## 1. 개요 및 목적

- **입력:** `data/demo-day-latest/capture/transforms.json` (240장 iPhone ARKit 캡처 메타데이터)
- **문제점:** 240장 전수 조합 매칭 시 $\frac{240 \times 239}{2} = 28,680$개의 이미지 쌍을 비교해야 하므로 막대한 연산 시간 소모 및 오매칭 위험 증가.
- **목표:**
  1. 궤적의 시차(Baseline), 회전각, 타임스탬프를 정밀 분석하여 `trajectory_analysis.json` 리포트 생성.
  2. **시간 인접 쌍 + 적정 베이스라인 쌍 + 루프 클로저 후보 쌍**으로 구성된 **약 1,200쌍 내외의 최적 매칭 그래프(`matching_pairs.txt`)**를 자동 산출.

## 2. 모듈 1: `tools/analyze_trajectory.py` 상세 규격

### ① CLI 인터페이스
```bash
uv run python tools/analyze_trajectory.py \
    --transforms data/demo-day-latest/capture/transforms.json \
    --output output/trajectory_analysis.json
```

### ② 계산할 핵심 메트릭
1. **인접 프레임 시간차 ($\Delta t_i = t_{i+1} - t_i$):**
   - 0.5초 기준 이상치 판정 (예: $\Delta t > 1.0\text{s}$)
2. **인접 프레임 이동 거리 ($b_i = \|p_{i+1} - p_i\|$):**
   - 유클리드 거리 (미터 단위)
3. **인접 프레임 회전각 ($\Delta \theta_i$):**
   - $R_{\text{rel}} = R_i^\top R_{i+1}$
   - $\Delta \theta_i = \arccos\left(\frac{\text{Trace}(R_{\text{rel}}) - 1}{2}\right) \times \frac{180}{\pi}$
   - 급회전 구간($\Delta \theta > 15^\circ$) 플래그 설정
4. **루프 클로저(Loop Closure) 후보 검출:**
   - 조건: $|i - j| \ge 30$ (시간 차이 최소 15초 이상)
   - 거리 조건: $\|p_i - p_j\| \le 1.2\text{m}$
   - 시선 방향 조건: $\cos(\mathbf{v}_i, \mathbf{v}_j) \ge 0.6$ (카메라 시선 벡터 내적)

### ③ 출력 JSON 스키마 (`output/trajectory_analysis.json`)
```json
{
  "total_frames": 240,
  "total_duration_sec": 123.44,
  "statistics": {
    "delta_t": { "min": 0.5165, "mean": 0.5165, "max": 0.5165 },
    "translation_step_m": { "min": 0.035, "mean": 0.166, "max": 0.415 },
    "rotation_step_deg": { "min": 1.97, "mean": 14.26, "max": 38.54 }
  },
  "fast_rotation_frames": [8, 13, 17, 24],
  "loop_closure_candidates": [
    { "frame_a": 32, "frame_b": 74, "distance_m": 1.00, "direction_cos": 0.99 },
    { "frame_a": 33, "frame_b": 74, "distance_m": 0.86, "direction_cos": 0.99 },
    { "frame_a": 18, "frame_b": 159, "distance_m": 0.87, "direction_cos": 0.74 }
  ]
}
```

## 3. 모듈 2: `tools/build_matching_graph.py` 상세 규격

### ① CLI 인터페이스
```bash
uv run python tools/build_matching_graph.py \
    --analysis output/trajectory_analysis.json \
    --output output/matching_pairs.txt \
    --temporal-radius 2 \
    --baseline-min 0.3 \
    --baseline-max 1.5
```

### ② 후보 매칭 쌍 선정 규칙
1. **시간적 인접 연결 (Temporal Continuity):**
   - 모든 프레임 $i$에 대해 $j \in [i-2, i+2]$ ($j \neq i$) 무조건 연결 ($\approx 480$ 쌍).
   - 이유: 높은 시야 겹침으로 트랙 추적의 연속성 보장.
2. **시차 확보 삼각측량 연결 (Parallax Baseline):**
   - 프레임 $i$로부터 인접 $k \in [3, 8]$ 프레임 중, 카메라 간 거리 $d(i, j) \in [0.3\text{m}, 1.5\text{m}]$ 및 시선 각도차 $< 30^\circ$인 쌍 연결 ($\approx 600$ 쌍).
   - 이유: 안정적인 삼각측량 깊이 계산을 위한 기하학적 베이스라인 확보.
3. **루프 클로저 연결 (Loop Closures):**
   - `trajectory_analysis.json`에서 검출된 상위 루프 후보 쌍 연결 ($\approx 50 \sim 100$ 쌍).
   - 이유: 120초 누적 VIO 드리프트를 단번에 묶어주는 전역 앵커링.

### ③ 출력 포맷 (`output/matching_pairs.txt`)
COLMAP의 `image_pairs_matching`에서 직접 읽을 수 있는 표준 텍스트 포맷:
```text
frame_000000.jpg frame_000001.jpg
frame_000000.jpg frame_000002.jpg
frame_000000.jpg frame_000004.jpg
...
frame_000032.jpg frame_000074.jpg
frame_000033.jpg frame_000074.jpg
```

## 4. TDD 단위 테스트 명세 (`tests/test_trajectory_and_graph.py`)

개발자는 반드시 다음 5대 단위 테스트를 통과하도록 구현해야 한다:
1. `test_trajectory_monotonic_timestamps`: 타임스탬프 단조 증가 및 간격 산출 검증.
2. `test_rotation_angle_computation`: 알려진 회전 행렬(예: $90^\circ$ 회전)에 대한 회전각 수식 정확도 검증.
3. `test_loop_candidate_filtering`: 인접 프레임(거리 가깝지만 시간도 가까운 경우)은 루프에서 배제되고, 시간 차가 충분한 쌍만 검출되는지 검증.
4. `test_matching_pairs_format`: 산출된 텍스트 파일이 한 줄에 공백으로 구분된 두 이미지 파일명을 갖추고 있는지 검증.
5. `test_pair_count_budget`: 총 생성된 쌍의 수가 1,500쌍 이하이며 중복(대칭 쌍)이 제거되었는지 검증.
